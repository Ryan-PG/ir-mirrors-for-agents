## ✨ این چیست؟

یک مجموعه‌ابزار کوچک و خودکفا که به **هر عامل کدنویسی** (Claude Code، ZCode، Cursor، Copilot Workspace و …) اجازه می‌دهد پکیج‌منیجرهای شما را به میرورهای ایرانی پیکربندی کند:

- 🧠 **اول می‌پرسد، بعد دست می‌زند** — شما ابزارها را انتخاب می‌کنید؛ چیز دیگری تغییر نمی‌کند.
- 🧪 **هر تغییر را تست می‌کند** — یک میرور فقط زمانی «پیکربندی‌شده» محسوب می‌شود که واقعاً پکیج را تحویل بدهد.
- 🔁 **به‌صورت خودکار به گزینه بعدی می‌رود** — اگر میروری در تست شکست بخورد، عامل تغییر را برمی‌گرداند و سراغ منبع بعدی در زنجیره می‌رود.
- 📜 **صادقانه گزارش می‌دهد** — خلاصه نهایی: چه تغییر کرد، چه چیزی موفق شد، چه چیزی شکست خورد و چطور به حالت قبل برگردید.

تمام داده‌های میرور از [thealibigdeli.ir/mirrors](https://thealibigdeli.ir/mirrors) گردآوری و در تاریخ **۲۰۲۶‑۱۱‑۱۹ ارائه‌دهنده‌به‌ارائه‌دهنده تأیید** شده است (هر endpoint واکشی و probe شده؛ شواهد خام در پوشه `_research/`).

## 🚀 شروع سریع

> پیش‌نیاز: هر عامل کدنویسی که بتواند دستور شل اجرا کند + فایل `MIRROR_CATALOG.md` در پوشه کاری.

1. **عامل کدنویسی خود را** در همین پوشه باز کنید.
2. **پرامپت را جای‌گذاری کنید** — [AGENT_PROMPT_FA.md](AGENT_PROMPT_FA.md) یا [AGENT_PROMPT_EN.md](AGENT_PROMPT_EN.md)، همه‌ی متنِ زیر خط جداکننده.
3. **به مصاحبه پاسخ دهید.** عامل فهرست شماره‌گذاری‌شده‌ای از ابزارهای پشتیبانی‌شده نشان می‌دهد — فقط موردنیازها را جواب دهید، مثلاً:

   > `۲ و ۴` — *فقط npm و apt اوبونتو*

4. **کارکردنش را ببینید.** برای هر ابزار عامل این چرخه را اجرا می‌کند:
   پشتیبان‌گیری → پیکربندی → تست → در صورت شکست، بازگردانی و امتحان میرور بعدی → گزارش.

تمام شد. هیچ چیز دیگری از سیستم شما دست‌نخورده می‌ماند.

## 🧠 رفتار عامل

```text
      ┌──────────────────────────────────────────────────────────┐
      │  گام ۱ · مصاحبه                                          │
      │  «کدام ابزارها را به میرورهای ایرانی سوئیچ کنم؟»          │
      │  → کاربر فقط ابزارهایی را انتخاب می‌کند که استفاده می‌کند   │
      └──────────────────────────┬───────────────────────────────┘
                                 ▼
      ┌──────────────────────────────────────────────────────────┐
      │  گام ۲ · برنامه‌ریزی (برای هر ابزار، از کاتالوگ)           │
      │  pip → ①RunFlare → ②Chabokan → ③IranServer → …            │
      └──────────────────────────┬───────────────────────────────┘
                                 ▼
      ┌──────────────────────────────────────────────────────────┐
      │  گام ۳ · اجرا (هر بار یک ابزار)                           │
      │   پشتیبان → اعمال گزینه ① → تست                           │
      │                 ├─ موفق ✅ → ابزار بعدی                   │
      │                 └─ شکست ❌ → بازگردانی → گزینه ② → تست    │
      │                              └─ شکست ❌ → بازگردانی → ③ … │
      │      هر گزینه‌ها شکست خوردند → ابزار دست‌نخورده می‌ماند     │
      └──────────────────────────┬───────────────────────────────┘
                                 ▼
      ┌──────────────────────────────────────────────────────────┐
      │  گام ۴ · گزارش (جدول + تغییرات + دستورات بازگردانی)       │
      └──────────────────────────────────────────────────────────┘
```

**تست، واقعی است:** میروری که فقط پاسخ می‌دهد قبول نیست — میرور باید مصنوع واقعی را تحویل بدهد (فایل پکیج دانلودشده، `apt-get update` موفق، image کشیده‌شده). شکست‌ها گذرا (یک تلاش دوباره با سقف ۲ برابر) یا قطعی (رفتن فوری به گزینه بعدی) دسته‌بندی می‌شوند.

## 🛠️ استفاده دستی (بدون عامل)

همه‌چیز شلِ معمولی است:

1. [MIRROR_CATALOG.md](MIRROR_CATALOG.md) را باز کنید → **بخش ۳** → ابزار موردنظر.
2. **گزینه ۱** را از جدول بردارید و قطعه‌کد *پیکربندی* را با endpoint همان گزینه اجرا کنید.
3. دستور *تست* را اجرا کنید. اگر شکست خورد، طبق خط *بازگردانی* اول برگردانید، بعد سراغ گزینه ۲ بروید.

## 🔐 ایمنی و نکات

- 🗂️ **پشتیبان‌گیری:** از هر فایل تغییر‌یافته نسخه هم‌مسیر با پسوند `.bak-YYYYMMDD-HHMMSS` ساخته می‌شود؛ گزارش نهایی بخش rollback دارد.
- 🛑 **بدون نزول امنیتی بی‌صدا:** گزینه‌هایی که به `trusted=yes`، `strict-ssl false` یا `GOSUMDB=off` نیاز دارند فقط با تأیید صریح شما اعمال می‌شوند (عامل موظف است اول توضیح بدهد).
- 🌍 **نقطه دید مهم است:** تأیید از خارج ایران انجام شده. سرویس‌هایی که IP خارجی را مسدود می‌کنند (DevNeeds ⚠️) ممکن است برای شما *بهتر* کار کنند؛ برعکس، همیشه روی دستگاه خودتان دوباره تست کنید — عامل این کار را خودکار انجام می‌دهد.
- ⚖️ **سهمیه و نکات:** سهمیه رایگان RunFlare = ۲۰۰۰ درخواست بر IP؛ مخازن apt چابکان امضادار نیستند؛ چند میرور فقط HTTP ساده دارند. همه در کاتالوگ علامت‌گذاری شده‌اند.
- 🩹 **بدترین حالت:** اگر همه گزینه‌های یک ابزار شکست بخورند، عامل آن ابزار را دست‌نخورده رها می‌کند — فقط زمان می‌گذرد، نه پیکربندی.

## 🔄 این داده‌ها چگونه ساخته شدند

1. فهرست ارائه‌دهنده‌ها از [thealibigdeli.ir/mirrors](https://thealibigdeli.ir/mirrors) استخراج شد (به‌همراه صفحات `/pypi-alternative` و `/ubuntu-solutions` و اسکریپت‌هایشان).
2. **صفحه هر ارائه‌دهنده** واکشی و هر endpoint با الگوهای استاندارد probe شد (`/v2/` رجیستری، `/simple/` پایتون، packumentهای npm، `/dists/` آپت، فهرست پوشه‌ها).
3. پوشش، تازگی همگام‌سازی و نکات خاص هر ارائه‌دهنده ثبت شد → [MIRROR_CATALOG.md](MIRROR_CATALOG.md)؛ شواهد خام در [`_research/`](_research) (`html/` و `notes/`).
4. تاریخ کاتالوگ **۲۰۲۶‑۱۱‑۱۹** است — میرورها می‌آیند و می‌روند؛ پیش از اتکا به گزینه‌های کم‌استفاده، تأیید را دوباره اجرا کنید (FAQ را ببینید).
